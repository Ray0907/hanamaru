# Hanamaru 0.1.0

Hanamaru's first public release packages a zero-production-dependency DOM annotation runtime, its optional modules, framework lifecycle adapters, and the responsive Annotation Inspector.

## Install

```sh
npm install hanamaru-annotations@0.1.0
```

```js
import 'hanamaru-annotations/style.css'
import { annotate } from 'hanamaru-annotations'

annotate('#claim', { mark: 'underline' }).show()
```

See the [Changelog](../../CHANGELOG.md) and [MIT License](../../LICENSE).

## Features

- Core: declarative scanning, imperative Annotation lifecycle, ordered Story playback, attached notes, and underline/highlight/circle/box/strike/bracket marks.
- Selection: clone one native selection into a regular Annotation controller.
- Group: preflight and control multiple annotations as one parallel atomic unit.
- Plugins: register deterministic, bounded custom SVG marks with seeded geometry helpers.
- Serialization: canonical `hanamaru/v1` definitions, restore, and target-only resolution for Annotation, Story, and Group.
- Shadow DOM: explicit exact-root scopes for open or retained closed roots, including Selection, Group, serialization, lifecycle ownership, and CSP-aware style modes.
- Frameworks: thin React `useAnnotation`, Vue 3.5 `useAnnotation`, and Svelte 5 `annotation` adapters with optional peers and no duplicate runtime.
- Inspector: select text, choose built-in or example-plugin marks, edit notes/options, apply, and copy honest HTML/JavaScript/JSON output at desktop or mobile width.
- Accessibility and security: decorative-by-default notes, opt-in `aria-describedby` ownership, keyboard Inspector semantics, reduced motion, bounded plugins, and strict-CSP Shadow modes.

## Size

Schema-v2 closure accounting uses gzip level 9. Main includes transitive local chunks plus base CSS; optional closures charge package chunks not already charged to main, with shared optional chunks conservatively charged to each entry. Shadow includes its separate stylesheet. Hard caps fail the build; stretch targets are report-only.

| Closure | Measured gzip bytes | Hard cap |
| --- | ---: | ---: |
| `main` | 28,156 | 28,672 |
| `iife` | 24,069 | 24,576 |
| `selection` | 1,084 | 3,072 |
| `serialize` | 10,577 | 11,264 |
| `group` | 4,881 | 8,192 |
| `plugins` | 2,087 | 6,144 |
| `shadow` | 20,032 | 21,504 |
| `react` | 2,926 | 4,096 |
| `vue` | 3,132 | 4,096 |
| `svelte` | 3,315 | 4,096 |

Main and IIFE are inside their hard caps and miss only their report-only stretch targets. Every optional closure is inside both hard and stretch thresholds.

## Verification

The prepared release gate runs non-empty unit and TypeScript suites, a fresh production build, export/dependency/dry-pack/size checks, full Chromium E2E, Firefox and WebKit smoke suites, and isolated React/Vue/Svelte endpoint tests. Packaging is verified by installing the exact tarball into an empty project, importing every entry, reading both CSS exports, confirming zero production dependencies, and recording SHA-512 outside the worktree.

Real-Chrome Inspector acceptance has exercised desktop idle/selected/editing/applied states, a 390×844 mobile dock and output sheet, keyboard-only mark selection, note editing, reduced motion, toolbar/note bounds, focus return, and zero horizontal overflow. The final 1280×900 README hero records the exact five-second path: select `Portable`, choose the Hanamaru flower example plugin, and Apply. It visibly retains the native selection and flower SVG, selected mark toolbar, status `Annotation applied. Output is current.`, and the HTML/JavaScript/JSON rail. The JavaScript panel honestly says to `register it with hanamaru-annotations/plugins` before running or restoring that custom mark. The capture contains no debug UI or personal data. This is local prepared/verified evidence; public main/tag CI and npm registry availability are intentionally not claimed before publication.

CI and tag verification use read-only `contents: read`, non-persisted checkout credentials, exact tag/package matching, and no npm token. The tag workflow produces the tarball once; publication and the GitHub Release use that same downloaded artifact rather than rebuilding it.
